# Agent 与子 Agent

一个 Agent 是一份可复用的配置包：人设、模型、能用哪些工具、能读哪些技能、能翻到哪些目录。配好之后在对话里一键切换。

> **关于名字**：设置页里这个东西叫「**Agent**」，创建按钮是「新建 Agent」；但对话界面里的切换下拉写的是「**助手**」。两个词指的是同一样东西，本文统一用 Agent。

配置位置：**设置 → YOLO → Agent → Agents**。

## 默认就有一个

内置一个叫 **Default** 的 Agent，**不能删除**。你不配置任何东西时用的就是它。

## 新建一个 Agent

点「新建 Agent」进入编辑器，左侧四个标签：**资料 / 工具 / 技能 / 工作区**。

### 资料

- **名称**、**描述**、**图标**
- **模型** —— 可以指定具体模型，也可以选「跟随默认模型」
- **System prompt** —— 这个 Agent 的人设和工作方式。右上角有放大按钮可以全屏编辑（Esc 关闭）

系统提示词里支持 `![[笔记名]]` **嵌入整篇笔记**。把长的规范、术语表、项目背景写成笔记再引用，比直接往框里塞一大段好维护得多。

下面还有三个开关：

| 开关 | 默认 | 作用 |
|------|------|------|
| **焦点同步** | 开 | 让 AI 感知你当前正在看哪篇笔记、PDF 的哪一页、网页的哪个位置 |
| **当前时间感知** | 开 | 把发消息时的时间注入给模型 |
| **读取项目指令文件** | 关 | 自动加载库根目录的 `AGENTS.md`、`CLAUDE.md` 当作项目指令 |

「读取项目指令文件」是为了兼容 Codex、Claude Code、Cursor 这些工具的项目约定文件。如果你的库同时也是个代码仓库，或者你已经写好了 `AGENTS.md`，打开它就能复用。

> 编辑器里**没有**温度、Top P 这类采样参数。那些参数配在模型本身上（[模型与提供商](./models.md#模型参数)），不在 Agent 这一层。

### 工具

先有两个总开关：**启用工具**、**包含内置工具**。

下面按类别列出所有能力，每一项可以单独启用，并设置审批档位（完全放行 / 需要审批 / 危险操作审批）。已连接的 MCP 服务器也列在这里，可以展开看它提供的每个工具。

面板顶部会显示已启用工具数和一个粗略的 **token 估算**——工具定义是要占上下文的，开得越多每轮消耗越大，这个数字能帮你权衡。

MCP 服务器还有两个额外的下拉：

- **披露模式** —— 「按需披露」只在系统提示里放一个工具名，模型要用时才加载完整定义；「常驻上下文」每轮都带上完整定义。工具多的服务器选按需披露能省不少 token
- **审批模式** —— 同上面的审批档位

> 全局「管理工具」里关掉的能力，在这里根本不会出现。全局是前置闸门，见[工具与权限](./tools-and-permissions.md)。

### 技能

列出所有技能，每个可以为这个 Agent 单独启用，并覆盖加载方式：

- **全量注入** —— 技能正文每轮都进上下文
- **按需加载** —— 只放名称和描述，模型判断需要时才加载正文

顶部同样有 token 估算，以及「全量注入 N 个 / 按需加载 N 个」的统计。已在全局禁用的技能不会出现在这里。

技能怎么写见 [Skills](./skills.md)。

### 工作区

打开「限制自主工作范围」后，可以指定这个 Agent 能自主浏览和编辑的目录。

这里有三条必须理解的规则（**尤其是第三条**）：

1. 你 `@` 引用的文件和当前打开的文件**永远不受限制**——范围限制的是 AI 自己去翻的能力，不是你主动递给它的东西
2. 记忆目录和已授权的技能目录**始终豁免**
3. **这不是安全边界**：如果这个 Agent 有终端命令或第三方 MCP 工具，范围可以被绕过

第三条的完整解释见[工具与权限](./tools-and-permissions.md#工作区范围限制它能自主翻到哪)。简单说：想要真隔离，靠的是不给它终端和不受信的 MCP，而不是靠这个范围设置。

## 在对话里切换

输入框上方有 Agent 选择器，也可以在输入框打 `@` 选「助手」分类。选「默认」表示不绑定任何 Agent，用全局系统提示词直接对话。

Quick Ask 浮层可以单独指定一个 Agent，和主对话用的不是同一个——比如主对话用一个严谨的研究型 Agent，Quick Ask 用一个轻快的写作助手。

## 怎么分 Agent 比较顺手

Agent 的价值在于**把"人设 + 权限"打包**，不是单纯换提示词。几个实际有用的切法：

- **按信任级别分**：一个只读的"提问"Agent（不给编辑能力），一个能动手的"整理"Agent（给编辑和终端）。需要它动手时才切过去，平时不用担心误操作
- **按项目分**：每个项目一个 Agent，工作区范围锁在该项目目录，系统提示词嵌入该项目的背景笔记
- **按语言或风格分**：写作助手固定用某套文风要求

# 子 Agent

子 Agent 是主 Agent 在跑任务时**自己派出去**的临时助手，用来处理可以独立完成的子任务。

## 它不是你手动触发的

你不能直接"启动一个子 Agent"。能做的是给主 Agent 这个能力，然后由它自己判断什么时候用。

配置步骤：

1. 在 Agent 编辑器的**工具**标签里启用「**派遣子 Agent**」（默认关闭）
2. 在能力的设置里配置**可派遣模型池**：从已有模型里选几个加进池子，设定首选模型。主 Agent 不指定模型时就用首选的

## 它和主对话什么关系

理解这几点能避免踩坑：

**子 Agent 看不到主对话的历史。** 它是隔离的临时会话，主 Agent 必须把所有必要信息写进派遣指令里。所以如果你发现子 Agent 做得驴唇不对马嘴，通常是主 Agent 没交代清楚上下文。

**它是异步的。** 派遣后立刻返回一个任务 ID，子 Agent 在后台跑，跑完把结果回传给主 Agent。**结果不会自动变成给你的回答**——由主 Agent 决定怎么用、要不要告诉你。

**它继承主 Agent 的模型和已授权工具**，但有两类被排除：不能再派遣子 Agent（防止无限套娃），不能用需要和你交互的工具（比如向用户提问）。

**它的工具调用照常需要审批**，走和普通工具一样的流程，只是聚合成「等待审批 · N 项」的卡片，可以全部同意或全部拒绝。

对话里出现子 Agent 卡片时，可以展开看它的活动记录、工具调用次数和 token 消耗。

## 什么时候值得开

子 Agent 适合"能独立说清楚、跑完给个结论"的活，比如"把这二十篇笔记各总结三句话"。主 Agent 派出去之后自己继续干别的，不用把二十篇笔记的正文全部拉进自己的上下文——**这是它最大的价值：隔离上下文消耗**。

反过来，需要反复和你确认、或者强依赖当前对话历史的任务，交给子 Agent 只会更糟。
