# 工具与权限

这一篇回答一个问题：**YOLO 到底能对我的东西做什么，以及我怎么管住它。**

如果你只想快速有个安全感，记住三件事：

1. **模式决定权限上限**。Ask 不能改你笔记的正文，Agent 能改库里的文件，Max 能碰本机任意文件。
2. **默认情况下，改文件和跑终端都要你点同意**。可以改成自动放行，但那是你主动做的选择。
3. **工作区范围不是沙箱**。它限制的是 AI 的自主行为，不是安全隔离——下面会详细解释这个区别。

## 工具是怎么组织的

YOLO 把能力打包成 13 个「工具能力」，你启用、禁用、配置审批的单位是能力，而不是单个工具。

管理入口：**设置 → Agent → 全局能力 → 工具 → 「管理工具」**。

这里的开关是**全局闸门**：在这里关掉，所有 Agent 都用不了。每个 Agent 还能在自己的配置里进一步收窄——两层是「与」的关系，全局开着、单个 Agent 关着，那个 Agent 依然用不了。

### 完整能力清单

| 能力 | 做什么 | 哪些模式能用 | 默认 | 默认审批 |
|------|--------|-------------|------|---------|
| **读取** | 读库内文件、Skill、已打开的网页 | Ask / Agent | 开 | 放行 |
| **虚拟终端** | 库内的沙箱 shell，`ls`/`grep`/`find` 检索，以及 `mkdir`/`mv`/`rm` | Ask / Agent | 开 | 危险操作审批 |
| **文件编辑工具集** | 局部修改或整篇重写笔记 | 仅 Agent | 开 | 需要审批 |
| **知识库检索** | 语义检索 + 关键词混合检索 | 全部 | 开 | 放行 |
| **联网搜索工具集** | 联网搜索、抓取网页正文 | 全部 | 开 | 放行 |
| **向用户提问** | 信息不足时暂停反问你 | 全部 | 开 | 放行 |
| **任务清单** | 自己拆解、跟踪多步骤任务 | Agent / Max | 开 | 放行 |
| **裁剪工具调用结果** | 把旧的工具结果移出后续上下文 | 全部 | 关 | 放行 |
| **压缩上下文** | 把较早对话压成摘要 | 全部 | 关 | 放行 |
| **分析沙箱** | 隔离环境跑 JavaScript 做计算统计 | 仅 Agent | 关 | 放行 |
| **终端命令** | 本机**真实**终端 | Agent / Max | 关 | 需要审批 |
| **派遣子 Agent** | 派出隔离的临时 Agent 跑子任务 | 全部 | 关 | 放行 |
| **本地文件工具集** | 读写**本机任意路径**的文件 | **仅 Max** | 开 | 放行 |

### 几个容易误解的地方

**「虚拟终端」不是真的终端。** 它是一个用 JavaScript 重新实现的沙箱 shell，挂载在你的库根目录上，碰不到操作系统的文件系统。真正能执行本机命令的只有「终端命令」这个能力，它默认关闭、仅桌面端、默认需要审批，而且**不允许设成"始终允许"**。

**Ask 模式不等于只读。** 虚拟终端在 Ask 下是开着的，也就是说 Ask 能执行 `mkdir`、`mv`、`rm`——它不改你笔记里的字，但能移动和删除文件。这类危险操作每次都会单独问你。

**联网搜索默认是放行的。** 也就是说默认配置下，AI 联网搜索、抓取网页不会弹窗问你。如果你介意这一点，去「管理工具」里把它的审批档位调高或直接关掉。

**「本地文件工具集」只在 Max 模式存在。** Agent 模式永远拿不到它。这是刻意的设计：Agent 走 Obsidian 的库接口，Max 才是真正操作本机磁盘的身份，两者互斥。

**分析沙箱的子权限要逐项开。** 即使你打开了分析沙箱，它的「网络请求」「库内只读」「读取已打开网页」「知识库查询」「加载外部脚本」还是各自独立的开关，每个第一次打开都有风险确认。其中「加载外部脚本」标注为**极高风险**——它能以浏览器标签页同等权限拉取并执行任意远程 JavaScript。

## 审批：它想动手时你怎么管

### 三种审批档位

每个能力可以设成：

- **完全放行** —— 不问，直接执行
- **需要审批** —— 每次调用都停下来等你确认
- **危险操作审批** —— 只有虚拟终端有这一档：只读命令和 `mkdir` 直接放行，`mv` 和 `rm` 逐条停下来问

档位在 **Agent 编辑器 → 工具** 标签里按 Agent 单独设置。MCP 外部工具也在同一处按服务器配置。

### 弹出审批时你的选项

- **允许** —— 只放行这一次
- **本对话内允许** —— 这轮对话里不再问
- **拒绝** —— 可以附上拒绝理由，模型会收到并调整
- **停止执行** —— 中止整个任务

虚拟终端和终端命令**不提供**「本对话内允许」，因为它们被刻意设计成不能绕过逐次确认。

### 自动放行（YOLO 开关）

Agent 和 Max 模式各自带一个「YOLO」开关，打开后当前模式下**所有工具调用都不再逐条确认**。

首次开启会弹风险提示，要勾选"我已了解风险"。提示里说的三件事都是真的：

- 工具调用不再逐条确认，但**危险命令前缀黑名单仍然拦截**
- 自主执行可能消耗较多 Token
- 请提前备份

**黑名单在任何情况下都生效**，包括自动放行模式。默认拦截这些命令开头：`rm`、`dd`、`mkfs`、`fdisk`、`shutdown`、`reboot`、`poweroff`、`halt`。可以在「配置终端命令」里增删。

## 工作区范围：限制它能自主翻到哪

配置位置：**Agent 编辑器 → 工作区**标签，打开「限制自主工作范围」，然后用可视化的目录选择器标记包含和排除。

### 三条必须知道的规则

**第一，你主动给的东西不受限制。** 你用 `@` 引用的文件、当前正在编辑的文件，AI 永远能读到，哪怕它们在范围之外。这个设计是对的——范围限制的是 AI **自己去翻**的能力，不是你**主动递给它**的东西。

**第二，记忆和 Skill 目录始终豁免。** 即使你没把它们写进包含范围，AI 依然能读写自己的记忆和已授权的 Skill。

**第三，也是最重要的——这不是安全边界。**

> 如果这个 Agent 启用了**终端命令**或**第三方 MCP 工具**，工作区范围可以被绕过。

原因不难理解：终端命令执行的是真实 shell，MCP 工具跑在外部进程里，它们都不经过 YOLO 的路径检查。所以工作区范围应该被理解为**"让 AI 专注在相关目录，别到处乱翻"的自主性约束**，而不是**"把 AI 关进笼子"的隔离机制**。

如果你真的需要隔离，正确做法是不给这个 Agent 终端和不受信的 MCP 工具，而不是依赖范围设置。

另外，YOLO 自己的内部数据目录（根目录下的 `data`）无论范围怎么设都对 AI 隐藏，访问时返回"文件不存在"而不是"越权"——这样连它的存在都不暴露。

## 运行时组件

有些能力依赖额外下载的运行组件，在 **设置 → 模块 → 运行组件** 里管理：

| 组件 | 支撑什么 | 关掉会怎样 | 体积 |
|------|---------|-----------|------|
| **分词器** | 计算上下文 token 数 | 无法精确做 token 预算 | 约 1MB |
| **PDF 引擎** | 提取 PDF 文本、渲染页面 | 读不了 PDF | 约 2.3MB |
| **Bash 引擎** | 虚拟终端 | 虚拟终端工具直接不可用 | 约 1.3MB |
| **嵌入引擎** | 本地跑嵌入模型（仅桌面端） | 本地嵌入不可用，检索退回远程嵌入服务 | 本体约 0.5MB + 运行时资源约 27MB |

这些组件下载到插件自己的目录里，**不在你的库内，不参与同步**，Obsidian 的文件列表里看不到。

> 注意区分两层概念：运行组件的开关管的是**这个组件存不存在**，「管理工具」里的开关管的是**工具对 AI 可不可见**。名字相近但不是一回事——比如关掉 Bash 引擎，虚拟终端就没有底层支撑了；而在管理工具里关掉虚拟终端，引擎还在，只是 AI 用不了。

界面上只有「启用 / 停用」，停用不会自动删除已下载的文件。想彻底回收空间需要手动去插件目录的 `runtime/` 下清理。

## 我该怎么配

几个常见立场对应的配置：

**「我只想安全地问问题」** —— 用 Ask 模式就好，不用动任何设置。

**「我想让它帮我改笔记，但每一步我要知道」** —— Agent 模式，不开自动放行，保持文件编辑的「需要审批」。

**「我信任它，让它自己跑完」** —— Agent + 自动放行。先确认你的库在 Git 里，或者至少 Obsidian 的文件恢复开着。

**「我不想让它碰某些目录」** —— 配工作区范围，同时**不要**给这个 Agent 终端命令能力，否则范围形同虚设。

**「我完全不想让它联网」** —— 去「管理工具」关掉联网搜索工具集。注意这不影响模型 API 本身的调用。
