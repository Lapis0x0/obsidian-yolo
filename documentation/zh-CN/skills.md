# Skills

技能是一份 Markdown 写的操作手册，教 YOLO 按你的方式做某一类事。

和[记忆](./memory.md)的区别：记忆是"关于你的事实"，技能是"做某类事的方法"。

## 它解决什么问题

假设你每次整理会议记录都要交代一遍"按讨论要点、决议、行动项三段分，行动项要带负责人和截止日期"。写成技能之后，你只要说"整理一下这份会议记录"，它自己就知道该怎么做。

技能的价值不在于省那几句话，而在于**方法固定下来了**，不会这次这样下次那样。

## 渐进式加载

技能分两级：

- **frontmatter**（名称 + 描述）—— 始终在上下文里
- **正文** —— 只在需要时才加载

模型**只根据描述判断要不要用这个技能**。这意味着描述写得好不好直接决定技能会不会被触发，比正文写得好不好更关键。

每个技能可以设成：

- **按需加载**（`lazy`，默认）—— 先只给描述，触发后才读正文
- **全量注入**（`always`）—— 正文每轮都在上下文里

技能不多时差别不大；技能一多，全量注入会明显吃上下文。默认按需就好，只有那种"每次都必须遵守"的规范才值得全量注入。

## 内置技能

YOLO 自带四个：

| 技能 | 加载方式 | 作用 |
|------|---------|------|
| **obsidian-cli** | 按需 | 通过终端驱动官方 Obsidian CLI，处理反链、属性、日记、命令面板这些普通文件工具够不着的操作 |
| **obsidian-output-format** | 全量 | 规定输出 Markdown 编辑建议时的格式约定 |
| **skill-creator** | 按需 | 教 AI 怎么写技能的"元技能" |
| **snippet-creator** | 按需 | 教 AI 怎么维护你的 `/` 快捷指令库 |

想自己写技能时，可以直接让 AI 用 **skill-creator** 帮你写——它知道格式要求。

## 自己写一个

技能放在库里的 `YOLO/skills/` 下（`YOLO` 是可改的根目录名，见 **设置 → YOLO → 其他 → 维护 → YOLO 根目录**），两种形式：

- **单文件**：`YOLO/skills/我的技能.md`
- **目录包**：`YOLO/skills/我的技能/SKILL.md`，需要附带脚本或参考资料时用

### 格式

```markdown
---
name: meeting-notes
description: 把会议原始记录整理成结构化纪要。用户粘贴会议内容、要求总结会议、或提取行动项时使用。
mode: lazy
---

# 会议纪要整理

## 何时使用
用户粘贴了会议记录或转录文本，或者要求总结会议、提取行动项。

## 步骤
1. 提炼参会人、议题、结论
2. 按「讨论要点 / 决议 / 行动项」三段输出
3. 行动项必须带负责人和截止日期，没写清楚的直接问用户

## 输出格式
用三级标题 `### 讨论要点`、`### 决议`、`### 行动项`
```

三个 frontmatter 字段：

- **`name`** —— kebab-case，库内唯一，同时是标识和显示名
- **`description`** —— **最重要的一行**。必须把"做什么"和"什么时候用"都写进去，因为模型只靠这句话决定要不要启用
- **`mode`** —— `lazy`（默认）或 `always`

### 描述怎么写才有效

对比一下：

- ❌ `description: 会议纪要工具` —— 模型不知道什么情况算"该用它"
- ✅ `description: 把会议原始记录整理成结构化纪要。用户粘贴会议内容、要求总结会议、或提取行动项时使用。`

好的描述同时回答了"这是干什么的"和"什么触发条件下该想起它"。写完之后可以自己检验一遍：如果你是模型，只看这句话，能判断出该不该用吗？

### 技能能用什么

技能只能使用库内的工具（文件编辑、虚拟终端等），**没有独立的外部 API 访问能力**。需要调外部服务的话，那是 [MCP](./mcp.md) 的活。

## 导入现成的技能

**设置 → YOLO → Agent → 技能 → 「导入技能」**，三种来源：

- **拖拽**文件或文件夹进来
- **选择文件 / 文件夹**
- **粘贴 GitHub 链接**，支持三种形式：
  - 整个仓库：`https://github.com/owner/repo`
  - 某个子目录（作为一个技能包）：`https://github.com/owner/repo/tree/main/path`
  - 单个文件：`https://github.com/owner/repo/blob/main/path.md`

同名冲突时可以选「全部覆盖」或「跳过冲突」。

> 从网上导入的技能就是一段会进入你系统提示词的指令。装之前扫一眼正文，确认它做的是你以为的事——尤其是包含终端操作的那些。

## 启用和禁用

两层：

- **全局**：设置 → YOLO → Agent → 技能列表，每个一个开关。关掉后所有 Agent 都用不了
- **按 Agent**：在 Agent 编辑器的技能标签里单独开关，还能覆盖加载方式

首次使用需要点一次「**初始化 Skills 系统**」，它会在你的技能目录下写入模板文件。
