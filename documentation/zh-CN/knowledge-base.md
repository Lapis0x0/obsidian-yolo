# 知识库与检索

给库建立索引之后，YOLO 才能真正"读过"你的笔记——不是靠你每次 `@` 指给它，而是能自己按语义找到相关内容。

配置位置：**设置 → YOLO → 知识库**。

## 没建索引会怎样

不建也能用。AI 有一个「知识库检索」工具，没有索引时它会**自动降级成纯关键词检索**——能找到字面匹配的笔记，但找不到"说法不同、意思相近"的内容。

界面上会提示：「知识库索引已关闭 · Agent 的『搜索』工具将只使用关键词检索」。

建了索引之后，同一个工具变成**向量检索 + 关键词混合**。你不需要切换任何"RAG 模式"，AI 自己会用。

## 开始建索引

要先有一个**嵌入模型**，否则点开启会被拦下。嵌入模型有两种来源：

### 用 API 嵌入模型

先在[模型](./models.md)标签页给某个提供商添加嵌入模型（比如 OpenAI 的 `text-embedding-3-small`），然后回到知识库标签页，在「API 模型」那一行选中它。

> **选中之后还要点一次「设为当前」才生效。** 这不是多余的设计——切换嵌入模型会让所有已有向量全部失效，等于全库重建索引。多这一步是为了让你不会因为手滑点错下拉框就触发一次全量重建。

### 用本地嵌入模型（不需要 API Key）

在嵌入模型区域有个「**本地（设备端）**」货架，模型直接跑在你电脑上，**笔记内容不出本机**。

**仅支持桌面端**，移动端会显示不可用。

可选模型：

| 模型 | 语言 | 维度 | 体积 | 说明 |
|------|------|------|------|------|
| BGE Small (English) | 英语 | 384 | 约 33MB | 轻量 |
| BGE Small (Chinese) | 中文 | 512 | 约 23MB | 轻量，中文库首选 |
| Multilingual E5 Small | 多语言 | 384 | 约 129MB | |
| Nomic Embed Text v1.5 | 英语 | 768 | 约 132MB | 长上下文（8192 token） |
| BGE-M3 | 多语言 | 1024 | 约 560MB（GPU 版约 1.05GB） | 质量高，重 |
| Qwen3 Embedding (0.6B) | 多语言 | 1024 | 约 1.13GB | 最重 |

点「下载」会显示进度并在完成后校验文件完整性。支持 **CPU / GPU（WebGPU）** 切换，设备不支持 GPU 时该选项会被禁用。

关于量化格式有个反直觉的点：**q8（int8 量化）模型只能跑 CPU，放到 WebGPU 上反而更慢**。部分模型提供专供 GPU 的 fp16 变体。Qwen3 因为是 decoder-only 结构，int8 量化会导致向量漂移，所以只提供 fp16——这也是它体积最大的原因。

本地嵌入依赖「**嵌入引擎**」这个运行组件。没装或被停用时会提示你先去启用，见[工具与权限](./tools-and-permissions.md#运行时组件)。

模型文件存在插件自己的目录下，**不在你的库里、不参与同步**。删除要在模型条目上点两次确认。

### 开启

嵌入模型就位后，点状态条上的「**开启并建立索引**」。索引进度会显示在状态条和底部状态栏，包括当前正在处理哪个库、百分比、当前文件名。

## 多知识库

你可以把库拆成几个独立的知识库，各自管不同的范围。比如「工作笔记」和「读书笔记」分开，检索时 AI 会**按名称和描述自动判断该查哪一个**。

点「**新建知识库**」，每个知识库能配的就四项：

- **名称** —— 必填，不能重名
- **描述** —— 可选，但建议写。**这段文字会提供给模型，帮它判断该检索哪个库**
- **包含 / 排除范围** —— 可视化目录选择器，悬停文件夹标记包含或排除。规则向子目录传递，子目录可以单独覆盖。不设任何规则 = 索引整个库

卡片上会显示状态（已就绪 / 索引中 / 待更新 / 排队中 / 需要关注）以及文档数、向量块数、占用体积。

> **所有知识库共用同一个嵌入模型**，也共用同一套分块设置。各自独立的只有索引范围。

## 索引的维护

### 自动更新

默认开启。你编辑笔记后，空闲约五分钟会自动把改动同步进索引。失败会按 5 / 15 / 30 分钟退避重试。

### 手动更新

- **状态条的「立即更新」** —— 立刻同步所有改动过的文件
- **单个知识库的「重建此库」** —— 在卡片的「…」菜单里
- **命令面板 → 更新修改文件的索引** —— 全部知识库，增量
- **命令面板 → 重建整个库索引** —— 全部知识库，全量重建

### 什么时候必须手动重建

有些改动**不会**自动生效，必须手动跑一次全量重建：

- 换了嵌入模型
- 改了分块大小

这两项改完只影响之后新索引的内容，已有的向量不会自动重算。改完记得重建，否则新旧向量混在一起，检索质量会莫名其妙地差。

## 高级设置

知识库标签页底部有一组默认折叠的高级设置，都是**全局**的，不分知识库：

| 设置 | 默认 | 说明 |
|------|------|------|
| **索引 PDF** | 开 | 大库里不需要检索 PDF 的话关掉能明显提速 |
| **分块大小** | 1000 | 改完需要手动重建索引才真正生效 |
| **最小相似度** | 0.0 | 调高可以过滤掉勉强相关的结果 |
| **限制** | 10 | 每次检索返回的结果条数 |
| **嵌入并发数** | 10 | 范围 1–24。**遇到 429 限流报错就调低它** |

> 用免费档或按分钟限额的嵌入服务（比如 Azure S0）时，并发数是最常见的报错来源。索引大量笔记时一下子打出去十个请求很容易触发限流，调到 2–3 通常就正常了。

状态条的「…」菜单里还有「**管理索引数据**」，可以看到各嵌入模型下的向量条目总数，并单独移除某部分索引。

## 检索是怎么发生的

你不需要做任何事。AI 判断需要查笔记时会自己调用「知识库检索」工具，它可以指定查哪个知识库（靠你写的名称和描述判断），不指定就合并所有知识库的结果。

如果你想强制它看某篇具体的笔记，用 `@` 引用更直接——引用是确定的，检索是概率的。
