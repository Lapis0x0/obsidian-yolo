# 记忆

记忆让 YOLO 跨对话记住你的偏好、习惯和长期背景，不必每开一个新对话就重新交代一遍。

## 记忆就是普通笔记

这是理解记忆系统最关键的一点：**YOLO 没有专门的"记忆工具"，记忆就是你库里的普通 Markdown 文件。**

AI 用读写文件的通用能力去维护它们。所以你随时可以打开来看、直接编辑、或者删掉——它们不是藏在某个数据库里的黑盒。

## 文件放在哪

默认在库里的 `YOLO/memory/` 下，分两级：

```
YOLO/memory/global/MEMORY.md        ← 索引，对所有 Agent 生效
YOLO/memory/global/<某条记忆>.md     ← 一条具体的事实

YOLO/memory/<Agent 名>/MEMORY.md     ← 索引，只对这个 Agent 生效
YOLO/memory/<Agent 名>/<某条记忆>.md
```

> **`YOLO` 这个根目录名是可以改的。** 在 **设置 → 其他 → 维护 → YOLO 根目录** 里修改，技能、记忆等目录都会跟着走。下文为了好读统一写 `YOLO/`，请按你自己的设置替换。

每个目录是一份 `MEMORY.md` 索引加若干条独立的事实文件，**一条事实一个文件**。

### 两级记忆的分工

- **全局记忆**（`global/`）：对所有 Agent 都成立的事实。你是谁、你的长期偏好、常用的工具链
- **Agent 记忆**（`<Agent 名>/`）：只对某一个 Agent 有意义的事实。比如"写周报时要按部门分组"只对那个周报 Agent 有用

Agent 的目录名由它的显示名转换而来，重名会自动加序号。如果你的 Agent 恰好叫 `global`，它会被放进 `global (assistant)/`，避免和全局记忆撞车。

## 索引和正文的关系

`MEMORY.md` 是索引，里面每行一条指向具体记忆文件的链接和一句话提要。

**索引会整份进入系统提示词，正文不会。** AI 先看索引判断哪条可能相关，需要时才去读那一条的正文。这个设计是为了省上下文——你可以攒很多条记忆，但每轮对话只为索引付费。

所以索引里的那句话提要很重要，它决定了 AI 能不能在对的时候想起这条记忆。

## AI 怎么自己写记忆

系统提示词里固定注入一套记忆规则，要求模型：

- 一条事实一个文件，frontmatter 要有 `name`（kebab-case，和文件名一致）和 `description`（一句话）
- **写清楚为什么**，不只是记结论——这样换个场景也能套用
- 新增前先查索引有没有同主题的，有就更新而不是新建
- 过时或错误的记忆要删掉，索引行一起删
- 写绝对日期，不要写"上周""三天前"
- 库里笔记已有的内容不要抄进记忆，改成指向那篇笔记
- 每次增删改，**同一轮里必须同步更新索引**

你可以直接对它说"记住这个"，也可以让它自己判断。

## 什么情况下不会写记忆

**Ask 模式下写不了。** 记忆靠文件编辑能力实现，而文件编辑只在 Agent 模式开放。Ask 能读记忆，不能写。

记忆规则本身是无条件注入的（即使你一条记忆都还没有），目的是让模型知道有这套机制存在。但没有写权限的模式自然用不上其中"写"的部分。

## 你自己怎么管

直接在 Obsidian 里打开对应文件编辑就行，它们就是普通笔记。

你手改 `MEMORY.md` 之后，系统提示词的缓存快照会失效，下一轮对话重新读取——也就是说改完立刻生效，不用重启。

> AI 自己写记忆的那一次不会触发这个失效（否则每写一条就要重建一次缓存），所以**模型刚写的记忆通常下个会话才完全生效**。

## 记忆和工作区范围

记忆目录**始终豁免**于工作区范围限制。即使你把某个 Agent 锁在某个子目录里，它依然能读写自己的记忆和全局记忆。

但**别的 Agent 的记忆目录不豁免**——一个 Agent 不会因为豁免规则就读到另一个 Agent 的私有记忆。

## 上下文里占多少

在对话的上下文占用弹层里，记忆有独立的一桶，可以直接看到它吃掉了多少 token。记忆攒多了记得回头清理——索引是每轮都要付费的。
