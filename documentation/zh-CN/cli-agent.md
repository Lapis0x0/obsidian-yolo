# CLI Agent

如果你已经在用 Claude Code、Codex 这类命令行 AI 工具，YOLO 可以直接在对话界面里驱动它们，让它们在你的库里干活——不用切到终端，也不用另外买 API。

**仅桌面端。** 这些运行时都要拉起本机子进程，移动端不可用。

## 支持哪些

| 运行时 | 说明 |
|--------|------|
| **Claude Code** | 功能最全的一档，唯一支持 Plan 模式 |
| **Codex** | 唯一能实时观察子任务执行的一档 |
| **Hermes** | |
| **Pi** | 可以在 Pi 和 omp 两个渠道间切换 |
| **omp**（Oh My Pi） | Pi 的变体，不单独占一行，从 Pi 那行切换渠道进入 |
| **Grok** | 能力最受限的一档，详见下方对比 |

## 用之前要准备什么

**这些是"本机运行时"** —— YOLO 做的是在本地拉起对应的 CLI 子进程，不是替你连它们的服务。所以：

1. 先在系统里装好对应的 CLI 工具
2. 完成它自己的登录鉴权（比如 `claude` 要先自己登录过）

装好之后 YOLO 会自动检测可执行文件。如果检测不到，去 **设置 → Agent → CLI 运行时**，为对应的 CLI 手动填可执行文件路径（`which claude` 或 Windows 上 `where claude` 的输出）。

路径填错时下面会出现红色提示说这个路径在本机不存在，会退回自动检测。

> 这个路径**只存在本设备，不随库同步**。换电脑要重新填。

## 怎么切过去

1. 打开任意对话（侧栏、标签页、分屏、独立窗口都行）
2. 顶部的运行时切换器，从「Agent」切到「CLI」
3. 出现「CLI 提供方」下拉，选一家

切过去之后，整条对话由那个 CLI 进程驱动，界面也会换成对应的会话视图。**它不再走 YOLO 自己的工具和权限体系**——权限由各家 CLI 自己管。

## 权限怎么选

顶部还有一组和 CLI 提供方正交的开关：**Agent / Plan 模式** 加一个 **YOLO（自动放行）** 开关。

不同 CLI 对这两个开关的实际映射不一样，因为各家原生的权限模型本来就不同。YOLO 只是提供了统一入口：

**Claude Code**
- Plan → 它原生的 plan 模式
- Agent（不开 YOLO）→ `acceptEdits`，自动接受文件编辑，其他工具仍按 Claude Code 自己的策略确认
- Agent + YOLO → `bypassPermissions`，跳过全部确认

**Codex**
- Plan → 审批策略 `on-request` + 沙箱 `workspace-write`（只有工作区可写）
- 不开 YOLO → 同上
- 开 YOLO → 审批策略 `never` + 沙箱 `danger-full-access`，不再区分工作区内外

**Grok** 没有 YOLO 开关。

> Codex 没有原生的 Plan 模式，选了会退化成"Agent + 关闭 YOLO"的等效权限。

## 和 YOLO 原生 Agent 比，差在哪

切到 CLI 之后你**得到**各家原生的生态（它们自己的技能、MCP、插件体系），但**失去**一批 YOLO 自己的界面能力。

下面这张表来自代码里的能力矩阵：

| 能力 | YOLO 原生 | Claude Code | Codex | Hermes | Pi / omp | Grok |
|------|:---------:|:-----------:|:-----:|:------:|:--------:|:----:|
| Plan 模式 | — | ✓ | — | — | — | — |
| YOLO 自动放行开关 | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| 原生技能面板 | — | ✓ | ✓ | — | — | — |
| 原生 MCP 状态面板 | — | ✓ | ✓ | — | — | — |
| 插件管理 | — | ✓ | — | — | — | — |
| **Agent（助手）选择器** | ✓ | — | — | — | — | — |
| **导出对话到库** | ✓ | — | — | — | — | — |
| **用 YOLO 的模型选择器** | ✓ | — | — | — | — | — |
| **生成中排队发消息** | ✓ | — | — | — | — | — |
| 图片附件 | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| 上下文压缩 | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| 重写已发送的消息 | — | ✓ | ✓ | — | ✓ | — |
| 子任务实时观察 | — | — | ✓ | — | — | — |

加粗的四项是 **YOLO 原生独有**的：切到任何 CLI 都会失去它们。其中最常被念叨的是「导出对话到库」——CLI 会话没法导出成笔记。

**Grok 整列都是空的**，它不支持图片、不支持上下文压缩、也没有自动放行开关。选它之前知道这一点。

## 会话会保存吗

会。CLI 会话有独立的会话索引，能在对话历史列表里找到并继续（历史里「我的对话」和「任务会话」是分开的）。

但这个索引是**设备本地的，不随库同步**。换一台电脑就看不到之前的 CLI 会话了——这一点和 YOLO 原生对话不同，原生对话的记录走的是可同步的数据目录。

## 什么时候该用它

**适合用 CLI 的情况**：你已经付了 Claude Code 或 Codex 的订阅，想复用额度；或者任务需要它们原生的技能和 MCP 生态；或者你就是习惯那套工作方式。

**还是用 YOLO 原生更好的情况**：需要按用途切换不同人设的 Agent；需要把对话导出成笔记存档；想在一个界面里自由切换不同厂商的模型；需要跨设备同步对话历史。
