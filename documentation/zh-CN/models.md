# 模型与提供商

YOLO 自己不提供模型，你需要接入至少一个。这一篇讲怎么接、怎么调，以及那几个「默认模型」各管什么。

配置位置：**设置 → YOLO → 模型**。

## 提供商

「提供商」是模型的来源——一个 API 服务商，或者你本机跑的推理服务。点「**添加提供商**」打开选择器，分这几类：

| 分类 | 包含 |
|------|------|
| **国际** | OpenAI、Anthropic、Gemini、Mistral、Perplexity、Groq、xAI、Together AI、Cerebras、SambaNova、Morph |
| **中国** | DeepSeek、月之暗面 Moonshot、智谱、豆包、硅基流动、阶跃星辰、MiniMax、混元、小米 MiMo |
| **路由聚合** | OpenRouter、APIMart、Fluxion AI |
| **云厂商** | Azure OpenAI、Amazon Bedrock |
| **本地** | Ollama、LM Studio |

选择器里还单独有一张「**自定义提供商**」卡片，用于任意 OpenAI 兼容端点。

### 自定义提供商

反代、自建网关、没被内置收录的服务都走这里。需要填：

- **ID** —— 只用于在你的列表里区分，随便取
- **API 密钥** —— 不需要的话留空
- **基础 URL** —— 比如 `https://api.example.com/v1`。表单里有「预览」能看到最终拼出来的完整地址，填错时很有用

还有一组高级选项，平时不用动，但出问题时它们就是解药：

| 选项 | 什么时候需要 |
|------|-------------|
| **无 Stainless 请求头** | 遇到 `x-stainless-os` 之类请求头引发的 CORS 报错时打开 |
| **使用 Obsidian requestUrl** | 绕过 CORS 限制。**代价是流式响应会被整体缓冲后一次性返回**，也就是失去打字机效果 |
| **网络请求方式** | 自动 / 浏览器请求 / Obsidian 内置请求 / 桌面直连。桌面端推荐「桌面直连」；移动端如果浏览器请求有问题，切「Obsidian 内置请求」 |
| **响应流式模式** | 自动 / 流式 / 非流式。上游不支持流式时手动切非流式 |
| **提示缓存** | 仅 Anthropic 系，默认开。见下方说明 |
| **自定义请求头** | 需要附加鉴权头或路由头时用 |

> **关于提示缓存**：Anthropic 的缓存写入有约 25% 的溢价，但命中缓存后的读取只要原价的约 10%。对话越长、重复前缀越多越划算，所以默认开着。只有当上游不支持或错误处理 `cache_control` 字段时才需要关掉。

### 用订阅账号登录（OAuth）

如果你已经订阅了 ChatGPT Plus / Pro 或 Claude，可以直接用账号额度，不必另外买 API。在提供商选择器里找带 **OAuth** 徽标的条目：

**ChatGPT OAuth** —— 两种登录方式：
- **浏览器登录**：点击后打开系统浏览器授权（**仅桌面端**）
- **设备码登录**：显示一个设备码，15 分钟内到授权页面输入完成绑定。不占用本地端口，端口冲突时用这个

**Gemini OAuth** —— 点「连接」走浏览器授权，**仅桌面端**。连接后显示账号邮箱和项目 ID。

**Claude OAuth** —— 用 Claude 订阅额度跑普通对话。拿 token 的方式有两种：
- **自动登录**（仅桌面端）：点一下，YOLO 自动执行 `claude setup-token` 并回填
- **手动**：自己在终端跑 `claude setup-token`，把 token 粘进输入框。Windows 上点自动登录也会打开终端窗口让你跑完再粘回来

登录之后照常给它添加聊天模型，在对话里正常选用，和别的提供商没有区别。

> 它和其他提供商有一点底层差异：请求由 **Claude Agent SDK** 承载，不走 HTTP 端点。所以它没有「网络请求方式」「响应流式模式」这类需要切换传输层的选项——那些设置对它不适用。

连接成功后面板会显示连接状态和 token 过期时间，也可以随时断开。Token 过期后重新登录或重新粘贴即可。

## 添加模型

提供商加好后，展开它的卡片，点「**添加聊天模型**」。

- **单个模式**：从自动获取的可用模型列表里搜索选择，或者手填「调用 ID」和「展示名称」
- **批量模式**：勾选多个一次性加入，用默认参数，加完再逐个微调

表头还有一个「**连通性测试**」，可以对单个或全部模型发测试请求，返回正常 / 失败 / 超时，顺便报首字延迟。新配完或者怀疑某个模型挂了，先跑这个。

> 正在被设为「默认聊天模型」或「对话命名模型」的模型**不能删除、也不能关闭启用开关**。界面不会提前禁用按钮，你点了才会弹提示——先去把默认模型换成别的，再回来删。

### 模型参数

每个模型可以单独配置：

**模型类型（推理档位）** —— 这一项选错会让思考类模型表现异常：

| 类型 | 附带参数 |
|------|---------|
| 非推理 / 默认 | 无 |
| OpenAI 推理 effort | 推理强度：minimal（仅 GPT-5）/ low / medium / high |
| Gemini thinking budget | 思考预算，单位是 token。`0` 关闭思考，`-1` 动态分配 |
| Anthropic 扩展思考 | adaptive + effort |
| 通用推理模型 | 无 |

**输入模态** —— 文本、图片、PDF 原生输入。**这是声明，不是开关**：勾了模型本身不支持的模态会导致调用直接失败；没勾的话，即使模型支持，你也无法在对话里上传图片。

**Provider 内置工具** —— Gemini、OpenAI、OpenRouter、Grok、DeepSeek 各家的服务端能力（比如它们自己的联网搜索）。这和 YOLO 自带的联网搜索是两套独立的东西。注意：**启用 DeepSeek 官方联网后，YOLO 自己的联网搜索工具会被自动关闭**，避免两套搜索互相打架。

**上下文窗口 token** —— 常见模型会自动填充。这个值不只是摆设：[对话](./chat.md#看上下文用了多少)里的上下文占用百分比要靠它才能算出来。

**最大输出 token**、**请求参数面板**（字段级开关，不启用就用提供商默认值）、**自定义参数**（附加任意字段，支持文本 / 数字 / 布尔 / JSON）。

嵌入模型还有一个额外的**维度**字段，通常自动探测，也可以手填。

## 几个「默认模型」分别管什么

YOLO 里不止一个默认模型，是几个互相独立的槽位。搞清楚它们的分工能省不少钱——比如把对话命名交给一个便宜的小模型。

| 槽位 | 在哪配 | 用在哪 |
|------|--------|--------|
| **默认聊天模型** | 模型 → 默认模型策略与提示词 | 所有对话界面默认用的模型 |
| **对话命名模型** | 同上 | 根据首条消息自动生成对话标题。**适合用便宜的小模型** |
| **嵌入模型** | 知识库标签页 | 所有知识库共用一个。换模型等于全部索引失效 |
| **续写模型** | 灵光写作设置 | Quick Ask 的续写档、选区改写用。**同时是 Tab 补全的兜底** |
| **Tab 补全模型** | 灵光写作设置 | Tab 补全优先用它；**留空就回退到续写模型** |

## 全局系统提示词

在「默认模型策略与提示词」区块，有一个**全局系统提示词**文本框，内容会加在每次对话的最前面。

这里有个不显眼但很实用的技巧：**支持用 `![[笔记名]]` 直接嵌入某篇笔记的全文**。也就是说你可以把你的写作偏好、术语表、项目背景写成一篇笔记，然后在系统提示词里引用它——以后改笔记就等于改提示词，不用回设置页。

同一个语法在每个 Agent 的系统提示词里也能用，见 [Agent](./assistants.md)。

## 请求失败怎么办

同一区块下还有两个和稳定性相关的设置：

- **启用自动恢复**（默认开）—— 流式请求超时或失败时，自动改用非流式重试一次
- **主请求超时**（默认 60 秒）—— 推理模型思考时间长，容易撞上这个限制。如果你在用重度思考模型并且经常超时，调大它
